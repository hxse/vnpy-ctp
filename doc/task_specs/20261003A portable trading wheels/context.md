# 独立交易 wheel 发布

## 使用场景与设计初衷

ccxt-proxy2 的 CTP 依赖以补丁源码包安装，镜像构建缓存失效会重复编译原生绑定。SDK 更新频率较低，适合独立生成可长期下载的跨平台 wheel，由应用固定版本消费。

## 方案对比

只保留镜像/uv 缓存能加速同机重建，但依赖缓存保留和相同环境，不能作为长期发布入口。独立仓库用 Actions 编译，Release 保存固定产物，可让应用直接安装。Actions Artifact 有保留期限，只适合作业内中转。

## 取舍结论

沿用现有补丁和原生库，按真实可用平台构建，全部验收后自动发布。每次 push 对应 HEAD 的独立版本，使用完整提交身份，防止重复运行改写旧链接。应用消费迁移另行处理，本次不修改 ccxt-proxy2。
